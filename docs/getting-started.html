작업을 하는 엔진과, 진행을 보는 화면

Agent Console은 작업을 대신 수행하는 엔진과 연결되는 사용자 인터페이스입니다. 두 프로젝트는 별도 저장소에 있습니다.

Agent Console

“어디에 무엇을 부탁할지” 입력하고 진행과 결과를 확인하는 화면입니다.

  • Runtime Profile: 실행 환경 등록
  • Workspace Check: 작업할 폴더 검사
  • Run Launcher: 요청과 실행 승인
  • Timeline · 상태 · 결과 요약

AI Agent Platform · ai-agent

요청을 받아 실제 작업을 수행하고, 그 진행을 Console에 알려주는 별도 실행 엔진입니다.

  • Main: 작업 분배와 흐름 관리
  • Developer: AI 개발 작업
  • Browser · Desktop: 자동화
  • Training: 모델 학습 파이프라인

현재 Launcher의 Developer 작업 흐름

  1. 1. 사용자 → Agent Console작업할 프로젝트 폴더와 요청을 입력하고 실행을 승인합니다.
  2. 2. Agent Console → AI Agent Platform등록한 별도 실행 엔진을 시작합니다. Console이 엔진의 코드를 포함하거나 직접 모델을 호출하지 않습니다.
  3. 3. Main → Developer → CodexMain이 작업을 분배하고, Developer가 Codex를 이용해 선택한 프로젝트의 파일을 작업합니다. 파일 변경과 도구 실행 권한은 ai-agent가 최종 판단합니다.
  4. 4. AI Agent Platform → 공개 실행 이벤트 → Agent Console“작업 시작”, “파일 생성”, “완료” 등의 기록이 돌아옵니다. Console은 이를 진행 화면으로 정리합니다. 공개된 실행 기록이며 모델의 내부 사고 과정이나 파일 내용은 아닙니다.

현재 Launcher는 로컬 Developer / Codex만 시작할 수 있습니다. Browser·Desktop·Training 상태를 표시하는 것과 해당 작업을 시작하는 기능은 다릅니다.

모든 구성요소가 각각 AI 모델인가요?
  • Main: Python 규칙으로 작업을 고르고 흐름을 관리합니다.
  • Developer: Codex를 활용하는 AI 기반 개발 기능입니다.
  • Browser: Playwright를 이용한 웹 자동화입니다.
  • Desktop: Windows UI Automation으로 창과 컨트롤을 조작합니다.
  • Training: 모델 학습·검사 파이프라인입니다. 작은 학습 테스트 성공은 모델 성능의 완성을 뜻하지 않습니다.

이 기능들은 별도 ai-agent에 속합니다. Agent Console은 이들을 구현하는 프로그램이 아니며, 모든 구성요소가 독립적인 언어 모델을 쓰는 것도 아닙니다.

문서 하나를 만드는 작업이라면

프로젝트 폴더를 선택하고 문서 생성을 요청하면 다음 순서로 진행됩니다.

  1. 01 요청폴더와 할 일을 입력
  2. 02 준비·검사Check Workspace로 폴더 확인
  3. 03 실행실행 허용과 Start 승인
  4. 04 결과 확인진행·파일 변경·종료 코드 확인
  5. 05 완료실제 파일을 보고 Launcher로 복귀
  1. Workspace는 수정 대상 프로젝트 폴더입니다. ai-agent가 설치된 폴더와 구분하세요.
  2. Prompt에 할 일을 적습니다. 높이는 [-] / [+]로 조절하고 Auto로 복원합니다.
  3. Allow execution을 직접 켠 후 Start Run을 누릅니다. 확인창에서는 Cancel이 먼저 선택됩니다.
  4. Main이 Developer 작업으로 연결하고 Developer가 Codex를 이용해 파일 작업을 수행합니다.
  5. Timeline에서 진행을 보고 Run result에서 결과를 확인합니다.
  6. 실제 파일과 변경 범위를 확인한 뒤 Back to Launcher로 돌아옵니다.

실제 검증은 README 또는 smoke 문서 한 개 생성과 진행·완료·복귀 확인에 한정됩니다. Launcher 검증 기록에서 범위를 확인하세요.

“간단한 웹페이지를 만들어줘”도 요청 흐름을 설명하는 예시가 될 수 있습니다. 다만 이는 동작 설명용 예시이며, Console에서 모든 웹페이지 생성과 품질 검증이 완료됐다는 뜻은 아닙니다.

현재 어디까지 진행됐나요?

패키지 0.2.0 · 후속 변경은 0.2.1 Unreleased입니다. UI/UX 개선은 현재 범위에서 마무리했으며, 2026-10-09 사용자 피드백으로 기본 기능의 실제 사용 동작을 확인했습니다. main 반영·검토 이력은 PR #1에서 확인할 수 있습니다. main 병합과 0.2.1 공식 릴리스는 별도이며, 새 태그·릴리스는 생성하지 않았습니다.

Agent Console

  • Verified — 구현·범위 내 검증 완료: Replay, Live Subprocess Monitoring, Timeline, Component Status, Run Summary, Runtime Profile, Workspace Check, Run Launcher.
  • Verified — 사용자 실제 실행: Developer/Codex 단일 문서 생성과 Launcher 복귀. Monitor 기록 · Launcher 기록
  • Implemented / Partially Verified: UI/UX polish 구현·합성 화면 검사·사용자 기본 동작 확인. 전문 디자인 검증과 모든 환경의 보장은 포함하지 않습니다.
  • Planned: Timeline Filter, Search, Run History. 아직 없습니다.
  • Not Supported: Web UI, Database, Remote Monitoring, 다른 Task의 Launcher.

별도 AI Agent Platform

별도 ai-agent README와 기존 검증 기록을 읽어 정리했습니다. 이번 점검에서 플랫폼 작업을 재실행하지 않았습니다.

  • Main — Implemented / Partially Verified: 규칙 기반 분배와 검증된 실행 흐름.
  • Developer — Verified: 제한된 개발·파일 생성 E2E.
  • Browser — Partially Verified: 관리된 localhost의 HTTP·렌더링·클릭·cleanup.
  • Desktop — Partially Verified: 새 빈 Notepad의 제한된 동작.
  • Training — Partially Verified: 작은 LoRA smoke와 checkpoint 저장·resume·reload. 코딩 특화 모델의 성능 검증이 아닙니다.
  • External Workspace / JSONL / 외부 Developer E2E — Verified: 외부 폴더 검사, schema v1 출력, 외부 README 한 개 생성.

Verified는 적힌 시나리오만 확인했다는 뜻입니다. Production Ready 또는 범용 자율 작업의 보증이 아닙니다.

01시작 전 준비

  • Python 3.11 이상이 필요합니다. 이 프로젝트는 Python 3.13.15와 Textual 8.2.8에서 동작을 검증했습니다.
  • 저장소를 clone하거나 다운로드한 뒤 압축을 풀어 agent-console 폴더에서 터미널을 여세요.
  • 최초 설치 시에는 패키지를 다운로드할 인터넷 연결이 필요합니다.

Windows에서는 폴더를 연 뒤 우클릭 메뉴의 ‘터미널에서 열기’를 사용할 수 있습니다. 현재 폴더에 pyproject.toml, src, tests가 보이면 준비된 것입니다.

PowerShell · Python 확인
python --version
macOS / Linux · Python 확인
python3 --version

아래 명령은 모두 저장소 최상위 폴더에서 실행하세요. 이미 설치를 마쳤다면 03 · 첫 화면 띄우기로 이동하세요.

02설치하기

명령을 한 줄씩 실행하세요. 가상환경은 이 프로젝트가 사용할 Python과 패키지를 별도 폴더에 모으는 공간입니다.

1. 프로젝트 전용 가상환경 만들기

PowerShell
python -m venv .venv
macOS / Linux
python3 -m venv .venv

2. Agent Console 설치하기

PowerShell
.\.venv\Scripts\python.exe -m pip install -e .
macOS / Linux
.venv/bin/python -m pip install -e .

-e .는 현재 폴더의 프로젝트를 설치합니다. 소스를 수정하면 다시 설치하지 않아도 반영됩니다. 이 안내서는 가상환경을 activate하지 않고 실행 파일의 위치를 직접 지정합니다.

3. 설치 확인하기

PowerShell
.\.venv\Scripts\agent-console.exe --help
macOS / Linux
.venv/bin/agent-console --help

확인할 결과: 도움말에 replay · run · profile · launch 명령이 보이면 설치 완료입니다.

03첫 화면 띄우기

replay는 이미 저장된 이벤트 파일을 읽는 명령입니다. 아래 샘플은 가상 데이터이므로 실제 Agent 실행이나 credential 준비가 필요 없습니다.

성공한 실행 살펴보기

PowerShell · 성공 샘플
.\.venv\Scripts\agent-console.exe replay tests/fixtures/successful_developer_run.jsonl
macOS / Linux · 성공 샘플

확인할 결과: COMPLETED · Events 12 · Errors 0 · Elapsed 4.315s

화면은 결과를 읽을 수 있도록 열린 상태로 유지됩니다. q를 눌러 닫은 다음 다른 명령을 실행하세요.

실패한 실행도 확인하기

PowerShell · 실패 샘플
.\.venv\Scripts\agent-console.exe replay tests/fixtures/failed_run.jsonl
macOS / Linux · 실패 샘플
.venv/bin/agent-console replay tests/fixtures/failed_run.jsonl

확인할 결과: FAILED · Events 8 · Errors 2. 샘플에 의도적으로 실패 이벤트가 들어 있습니다.

필요할 때 붙이는 옵션

옵션언제 사용하나요?
--delay 0.2파일의 각 줄을 0.2초 간격으로 읽어 흐름을 천천히 봅니다. 기록된 시간에 맞춘 재생은 아닙니다.
--plain전체 화면 대신 최종 텍스트 보고서를 출력하고 종료합니다.
--tui대화형 터미널 화면을 명시적으로 사용합니다. stdin replay에는 사용할 수 없습니다.

예를 들어 성공 샘플 명령 끝에 --plain을 붙이면 간단한 보고서로 확인할 수 있습니다.

04화면 읽는 법

화면 영역의미
Run 선택 / 상태어떤 실행을 보고 있는지와 전체 결과를 표시합니다. 여러 run이 있으면 상단에서 선택합니다.
Timeline실행 기록을 sequence 순서로 보여줍니다. 오류는 색상과 ERROR 문구로 구분합니다.
Agents / System여섯 Agent 상태와 Main·Workspace·Git 등 보조 구성요소의 마지막 상태를 구분해 표시합니다.
Current activity / Run result실행 중에는 최근 작업, 종료 시에는 결과·프로세스 종료 코드·최근 파일 변경을 보여줍니다.
Run summary기록된 경과 시간, 이벤트 수, 오류 수를 요약합니다. Issues는 입력·관측 진단 수입니다.

Tab 영역 이동 · ↑ ↓ 목록 탐색 · q 종료 · Ctrl + C 중단

어떤 component가 실패해도 재시도 후 run 전체는 성공할 수 있습니다. 전체 결과는 run.completed, run.failed, run.cancelled를 기준으로 판단합니다. 종료 이벤트가 없으면 Incomplete로 표시합니다.

권장 터미널 크기는 80열 × 24행 이상입니다. Elapsed는 이벤트에 기록된 시간이며 replay를 기다린 실제 시간과는 다릅니다.

05실시간으로 보기

run은 외부 명령을 실행하고 그 명령의 stdout에서 JSONL 이벤트를 받습니다. 먼저 샘플을 한 줄씩 내보내는 예제 프로그램으로 연결을 확인하세요.

PowerShell · 실시간 샘플
.\.venv\Scripts\agent-console.exe run -- .\.venv\Scripts\python.exe -u examples/emit_fixture.py tests/fixtures/successful_developer_run.jsonl
macOS / Linux · 실시간 샘플
.venv/bin/agent-console run -- .venv/bin/python -u examples/emit_fixture.py tests/fixtures/successful_developer_run.jsonl

이벤트가 차례로 나타나고 마지막에 COMPLETED / Process exit 0이 표시됩니다. q로 화면을 닫으세요.

-- 앞은 Agent Console의 옵션, 뒤는 실행할 외부 명령입니다. Python의 -u는 출력을 모아두지 않고 바로 전달하도록 합니다.

06실제 작업 시작하기

별도로 준비한 ai-agent와 기존 인증 환경이 필요합니다. Runtime Profile은 그 엔진의 Python 실행 파일, main.py 위치, 기본 모델을 기억하는 로컬 설정입니다. 비밀번호 보관함이 아닙니다.

Runtime Profile 등록 명령과 상세 절차를 따라 등록하세요. 여기서 경로는 자신의 별도 ai-agent 설치 위치로 바꿉니다. 작업 대상 프로젝트 폴더는 Launcher의 Workspace에 따로 입력합니다.

PowerShell · local 프로필 등록 후
.\.venv\Scripts\agent-console.exe launch --profile local
macOS / Linux · local 프로필 등록 후
.venv/bin/agent-console launch --profile local

Workspace 선택 → Check Workspace → 결과 확인 후 복귀 → Prompt 입력 → Allow execution ON → Start Run → 확인창 Start 순서로 진행합니다.

Check 성공은 실행 승인이 아닙니다. 실제 파일 변경 권한은 ai-agent가 최종 판단합니다. 실행 중 Cancel Run 또는 q / Ctrl+C는 직접 시작한 프로세스만 종료합니다. 하위 프로세스 전체 종료를 보장하지 않으며 자동 실행 시간 제한은 없습니다.

이미 공개 JSONL을 출력하는 명령이 있다면

agent-console run -- <실행파일> <인자들>로 직접 연결할 수 있습니다. stdout은 schema v1 JSONL, 일반 진단은 stderr로 보내고 각 줄을 즉시 flush해야 합니다. 외부 프로그램은 현재 작업 폴더와 환경을 상속하며 대화형 stdin은 지원하지 않습니다.

replay -는 stdin의 이벤트를 받아 입력 종료 후 plain 보고서를 출력합니다. README의 사용 예를 참고하세요.

Console은 prompt history나 수신 이벤트를 기본 저장하지 않습니다. 실행 시작 후 입력과 undo 기록을 비우지만, 실행 중 OS 프로세스 조회에는 prompt 인자가 보일 수 있습니다. 별도 ai-agent의 로그 정책은 Console과 별개입니다.

막혔을 때 확인할 것

python 또는 agent-console 명령을 찾을 수 없어요

Python 3.11 이상이 설치되어 있는지, 현재 폴더가 저장소 root인지 확인하세요. Windows에서 python 대신 py만 인식된다면 py -3 --version으로 버전을 확인한 뒤 py -3 -m venv .venv로 생성할 수 있습니다. 이후에는 안내서의 .venv 실행 경로를 그대로 사용하세요.

Activate.ps1 실행이 차단됐어요

이 안내서의 명령은 가상환경 활성화가 필요 없습니다. PowerShell 실행 정책을 바꾸지 않아도 .\.venv\Scripts\python.exe와 .\.venv\Scripts\agent-console.exe를 직접 실행할 수 있습니다.

화면 대신 글자 보고서만 나와요

출력이 terminal이 아니면 자동으로 plain mode가 됩니다. 일반 터미널에서 실행하거나 --tui를 사용하세요. run에서는 run --tui -- ...처럼 외부 명령을 구분하는 -- 앞에 옵션을 넣습니다. stdin replay는 plain mode만 지원합니다.

이벤트가 한꺼번에 나오거나 계속 기다려요

producer가 stdout을 buffering하고 있을 수 있습니다. Python 명령은 -u를 사용하거나 이벤트마다 flush하도록 설정하세요. plain mode는 입력 종료까지 기다립니다. terminal event를 보냈더라도 producer 프로세스가 계속 살아 있으면 구독도 계속됩니다.

Malformed JSON / Compatibility error가 보여요

stdout에 일반 문장이 섞였는지, 한 줄이 완전한 JSON event인지 확인하세요. 지원 버전은 schema_version: 1입니다. 잘못된 줄은 건너뛰고 다음 줄을 처리합니다.

Incomplete 또는 sequence gaps가 보여요

실행 종료 이벤트가 없거나 중간 이벤트가 누락됐습니다. producer의 종료 상태와 event log가 완전한지 확인하세요. Agent Console은 입력이 끝났다는 이유만으로 실행을 성공으로 처리하지 않습니다.

stderr가 있는데 내용은 보이지 않아요

민감 정보 노출을 줄이기 위해 수신 byte 수만 표시합니다. producer가 제공하는 별도의 안전한 진단 방법으로 원인을 확인하세요. 전체 run이 Completed여도 subprocess 종료 코드가 0이 아니면 CLI는 실패를 반환합니다.

터미널이 작거나 이벤트가 너무 많아요

창을 키우거나 --plain으로 실행하세요. TUI에는 최근 1,000개, plain에는 최근 200개 이벤트가 표시됩니다. 보관 한도는 session당 20개 run, run당 10,000개 이벤트이며 한도를 넘으면 명시적인 입력 오류로 보고합니다.

개발자를 위한 기술 구조

사용자 흐름을 이해했다면 아래에서 내부 경계를 확인할 수 있습니다. Python 3.11+와 Textual을 사용하며 core는 TUI에 의존하지 않습니다.

RuntimeProfile + LaunchRequest
  → CommandBuilder: shell 없는 argv
  → 별도 ai-agent subprocess
  → stdout JSONL (또는 파일 / stdin replay)
  → Parser → Event → Reducer → RunState
  → Textual TUI / plain report
  • Profile / Request: 실행 환경과 이번 요청을 검증합니다.
  • subprocess: stdout과 stderr를 동시에 읽습니다. stderr는 원문 대신 byte 수만 집계합니다.
  • Parser / Event: schema v1을 검증하고 허용된 정보만 남깁니다.
  • Reducer / RunState: 실행별 sequence 순서로 상태를 계산합니다. 늦게 온 이벤트를 재정렬하고 중복·충돌을 구분합니다.
  • TUI: 계산된 상태를 표시합니다. UI가 upstream 완료 이벤트를 만들어내지 않습니다.

한 줄 64 KiB, 세션 20개 run, run당 10,000개 이벤트로 제한합니다. Timeline은 최근 1,000개를 표시합니다. 한도를 넘으면 진단하고 성공으로 처리하지 않습니다.

대량 입력의 중복 탐색은 선형이며 Timeline은 최근 행을 다시 구성합니다. 장시간·대량 부하의 성능 보증은 현재 범위가 아닙니다. 하위 프로세스가 pipe를 열어 두면 stream 종료가 지연될 수 있습니다.
